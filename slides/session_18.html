Definition
What Is a Design System?
A design system is a shared library of reusable components + rules + documentation that a team uses to build products faster and more consistently.
🎨
Style Guide
Colors, fonts, spacing rules. The "what it looks like" part. Usually a PDF or a static page.
🧩
Component Library
Buttons, inputs, cards — reusable Figma (or code) components. The "building blocks" part.
📖
Documentation
Rules for when to use each component, do's and don'ts, usage examples. The "how to use it" part.
🔗
Design Tokens
Named values for every design decision — `--primary-500: #7C3AED`. Connects design to code.
👥
Shared Language
Designers say "Primary Button" and devs know exactly what component to render. Same name, same thing.
🚀
Speed
No more rebuilding a button from scratch on every screen. Pick it from the library and move on.

Components
Component Anatomy in Figma
Variants
One component, many states. Button has: Size (S/M/L) × Type (Primary/Secondary/Ghost) × State (Default/Hover/Disabled). All live inside one Figma component set.
Properties
Boolean properties (show/hide icon), Text properties (change label without entering the component), Instance swap (swap the icon). These make components flexible without breaking them.
Slots
A "slot" is a placeholder inside a component where any content can go. A Card component has an image slot, a title slot, a body slot, and an action slot.
Auto Layout
Always build components with Auto Layout. It makes them resize correctly when text changes, when icons are toggled, or when the screen size changes.

Comparison
Style Guide vs Design System

Style Guide

  • 📄 Usually a static PDF or web page
  • 🎨 Covers: brand colours, fonts, logo usage, tone of voice
  • 👁 Primarily for visual consistency
  • ✅ Good for: brand identity, marketing teams, agencies
  • ❌ Not interactive — no reusable components

Design System

  • 🧩 A living library of components + rules + code
  • 🔗 Connected to code — tokens map to CSS variables
  • 👥 Shared between design and engineering
  • ✅ Good for: product teams, apps, large-scale products
  • 🔄 Always evolving — versioned like software
Rule of thumb: if one designer → style guide is fine. If a team ships a product → you need a design system.

How To
Start Your Own System
01

Define your colour palette

5–7 main colours + their shades. Name them semantically: Primary, Secondary, Error, Warning, Success, Surface.

02

Set your type scale

2 font families max. 5–6 type sizes: display, h1, h2, body, caption, label. Set line-height for each.

03

Define spacing

4px base grid. Multiples: 4, 8, 12, 16, 24, 32, 48, 64. Never use a spacing value not in this scale.

04

Build foundational components

Button, Input, Card, Badge, Modal, Toast. These 6 cover 80% of all UI needs.

05

Document every component

For each: screenshot, do/don't examples, variant table, usage rules. A component without docs is not a system.

Hands-On
Activity — Build a Mini System
Your Task (20 min)
  1. In Figma, create a new page called "Design System".
  2. Define 5 colour styles (Primary, Secondary, Error, Surface, Background).
  3. Create a Button component with 2 variants: Primary and Secondary, each with Default/Hover states.
  4. Bonus: Create an Input component with Default/Focus/Error states.

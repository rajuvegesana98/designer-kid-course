UI Patterns

Modals & Overlays

Modals interrupt users to demand a decision. Use them only when the action can't wait or context matters.

Confirm Delete
Are you sure you want to delete "Session 01 Slides"? This action cannot be undone.
Use modals for
Confirm destructive actions, collect essential info, display previews
Avoid modals for
Marketing messages, non-critical info, anything with lots of scrolling
Atomic Design

Building Blocks → Systems

Brad Frost's model: design smallest first, compose upward. Every screen is atoms stacked into organisms.

Atoms
Button, input, label, icon, colour token, font size
Molecules
Search field = input + button + icon combined
Organisms
Nav bar = logo + links + search + CTA all together

Key Takeaway
"Design familiar patterns. Invent new interactions only when familiar ones genuinely can't do the job."
— UI Pattern Principle
🧱
Use Components
Don't reinvent buttons and inputs — spend creativity on the unique parts
🔄
Design All States
Default, hover, focus, disabled, error — incomplete states cause bugs
⚙️
Think in Systems

Screenshot 2–3 screens and list every UI component you can identify

Concept 01
What is a User Persona?
A persona is a fictional character built from real research. It represents a group of similar users as one specific person — so you always have someone to design for.
🧑
Based on Real Research
Not invented — built from patterns across multiple user interviews and observations. One persona represents many real people.
🎯
Keeps Design Focused
When the team debates a feature, the persona answers: "Would Priya use this?" It cuts arguments and keeps everyone aligned.
📋
Has a Full Profile
Name, age, job, goals, frustrations, daily habits, tech comfort level — enough detail to feel like a real person.
🚫
Not a Stereotype
A persona is specific, not generic. "A 26-year-old who hates complicated menus" beats "a young urban professional."
💡 Think of it like a character in a film. A good script writer knows their character so well they can predict exactly how they'd react in any situation. That's how you should know your persona.
Concept 02
A persona in action
Here's a sample persona — built from research on a food-tracking app.
👩
Priya Sharma
28 · Software Engineer · Bengaluru
Goals
Eat healthier, reduce food waste, spend less time grocery shopping
Frustrations
Forgets what's in the fridge, orders food when she has ingredients at home
Tech level
High — uses 8+ apps daily, expects everything to be fast and simple
Quote
"I always buy more vegetables thinking I'll cook — and then throw them away a week later."
What Priya needs from the app
Quick way to log food items — under 10 seconds per item
Expiry reminders 2 days before something goes bad
Simple home screen — no clutter, just what matters now
What would frustrate Priya
A complicated onboarding flow with too many questions
Notifications that feel spammy or arrive at the wrong time
Any feature that requires more than 2 taps to complete
Design decisions Priya drives
Minimal home screen — only today's expiring items shown first
Barcode scan as the primary add-item method — fastest possible
Concept 03
What is a User Flow?
A user flow maps every single step a user takes — from entering your app to completing a goal. It's a diagram, not a design.
🗺️
A Path, Not a Screen
A user flow shows the journey — decisions, steps, branches. Not what the screens look like. That comes later in wireframing.
🔀
Shows Every Branch
What happens if the user taps the wrong button? What if they forget their password? Flows show all paths — happy and unhappy.
✅
Reveals Complexity Early
If your flow has 12 steps to complete a simple task — that's your signal to simplify before you design a single screen.
🏗️ Analogy: An architect draws a floor plan before building walls. A UX designer maps the user flow before designing screens. The plan reveals the problems before they're expensive to fix.

Concept 05
User Flow vs Task Flow
They look similar. Here's exactly how they differ — and when to use which.
User Flow
Includes entry points — where does the user come from? (notification, home screen, deep link)
Shows the full experience — decisions, errors, alternate paths
Tied to a specific user and their goal
Used during: UX research and early planning
Example: "Priya sets up expiry reminders for the first time"
Task Flow
Starts inside the product — assumes the user is already in the app
Shows one specific task — linear, no branching
Not tied to a specific person — any user doing this task
Used during: wireframing and developer handoff
Example: "Add a new food item via barcode scan"
🧭 Simple rule: Use a User Flow when planning the experience. Use a Task Flow when explaining a specific interaction to developers or in wireframes.
How To
Building a persona + flow step by step
You don't need Figma for this. Paper and a pen is how professionals start too.
Building a Persona
1. Review your research — find patterns across users
2. Pick the most common user type
3. Give them a name and photo (or avatar)
4. Fill in: goals, frustrations, quote, tech level, daily context
5. Keep it to one page — if it's longer, it won't be used
Building a User Flow
1. Pick one task your persona needs to complete
2. Write the entry point — how do they arrive?
3. List every action they take, in order
4. Add decision points — what choices do they face?
5. End at the goal — task completed, confirmation shown
✏️ Pro tip: Draw it on paper first. Use sticky notes — one step per note. Rearrange until the flow feels obvious. Then move to Figma or a whiteboard tool.
Key Takeaway
"
A persona gives you someone to design for. A user flow gives you a path to design through.
Together, they make sure you're solving the right problem for the right person in the right way.

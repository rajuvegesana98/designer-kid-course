The Problem
Why Handoff Goes Wrong
Most implementation mistakes aren't coding errors — they're communication gaps.
😬
Missing specs
No padding or font sizes noted — developer guesses and gets it wrong.
🎨
Inconsistent colours
Designer uses 12 shades of grey across the file — developer picks one at random.
📁
No assets exported
Icons and images buried in the Figma layers, no exports set up.
❓
Missing states
Only the default state designed — hover, error, empty state left for the dev to invent.

Essentials
What Developers Need From You
📐
Spacing & sizing
Width, height, padding, margin — in px or rem. Use a consistent 8px grid.
🖋
Typography
Font name, weight, size, line-height, letter-spacing for every text style.
🎨
Colour tokens
Named colours: Primary/500, Error/300 — not raw hex. Matches the code variables.
🖼
Exported assets
Icons as SVG, images as PNG/WebP at 1x and 2x. Named clearly.
🔄
All states
Default, hover, focus, disabled, error, loading, empty — every variation.
📱
Responsive rules
What changes at tablet and mobile — layout, font sizes, hidden elements.

Tools
Handoff Tools

Figma Dev Mode

  • Developers switch to Dev Mode to inspect any layer
  • Shows exact spacing, fonts, colours, and code snippets
  • Download assets directly from the panel
  • Comment threads visible right on the design
  • Best option if your team already uses Figma

Zeplin

  • Dedicated handoff tool, connects to Figma/Sketch
  • Generates style guides and component specs automatically
  • Great for teams with separate design and dev orgs

Design Tokens

  • Named values (colours, sizes) shared between Figma and code
  • Change once, updates everywhere — design and production stay in sync
  • Tools: Token Studio (Figma plugin), Theo, Style Dictionary

Specs
How to Write Design Specs
Annotations on your Figma file tell developers what the numbers mean — not just what they are.
Red-lines (manual)
Draw dimension lines and callouts on a separate "Specs" frame. Use a red or contrasting colour. Notes like "16px gap between icon and label" or "border-radius: 8px on all corners".
Component notes
For each component, write: what it's used for, which states exist, what triggers each state, any animation or transition detail (e.g. "300ms ease fade on hover").
Auto-annotations
Plugins like Figma's built-in "Inspect" or "Redline" plugin generate spec overlays automatically — saves time on simple screens.
Naming convention
Name layers clearly: Button/Primary/Default not Rectangle 42. Devs read layer names in Dev Mode — a clean naming system speeds up implementation dramatically.

Collaboration
Working With Developers

Do this

  • Involve developers early — share in-progress designs, not just finals
  • Explain the why, not just the what — "this spacing creates visual hierarchy"
  • Do a walkthrough call when you hand off a complex screen
  • Be reachable during build — answer questions fast
  • Do a design QA pass before launch — compare built vs designed

Avoid this

  • Throwing a Figma link with no context and going silent
  • Saying "just match what's in Figma" when the design isn't complete
  • Changing the design after it's been built without flagging it
  • Designing things that are technically impossible or extremely expensive to build
  • Treating developers as pixel-pushers rather than collaborators

Quality Check
Design QA Review
After the dev builds it, you review it — just like a developer does code review.
01

Open side by side

Figma design on one screen, built product on the other. Compare directly.

02

Check spacing & sizing

Use browser DevTools to inspect padding/margins. Is the 8px grid respected?

03

Check colours & fonts

Are all colours from the token system? Are font weights and sizes correct?

04

Test all states

Hover, focus, disabled, error — do they all behave as designed?

05

Log issues clearly

File feedback in Jira/Notion: include a screenshot, the exact problem, and the expected fix.

Hands-On
Activity — Handoff a Screen
Your Task (20 min)
  1. Pick one screen from your existing wireframe or design project.
  2. On a new Figma frame, annotate it: spacing, font sizes, colour names, asset exports.
  3. Write component notes for one component (at least 3 states).
  4. Share your link with a partner and "review" theirs — is it clear enough to build?
